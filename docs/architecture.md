# Architecture

[Українською](architecture.uk.md)

**In short.** The world is run by a deterministic core in Rust (`crates/teul-core`). It is compiled to WebAssembly (`crates/teul-wasm`), and the TypeScript client (`app/src`) only asks the core and draws the frame. The content (maps, items, residents, stations, stories) is generated by Python scripts into a single file, `content/base/pack.json`. A save is an event log in IndexedDB, signed by a chain and verified by re-executing the inputs. Music is pre-rendered by `crates/teul-music`. On Android everything runs through Capacitor (`app/android`), on a computer through Tauri (`desktop/`).

## Layers

| Layer | Where | What it does |
|---|---|---|
| Core | `crates/teul-core/src` | World state, commands, events, rules, the simulation of life, the calendar. Integer arithmetic only, no clock, no `f64` |
| Bridge | `crates/teul-wasm/src` (`engine.rs`, `lib.rs`) | Exports `Engine` to JS: `apply`, `*_view(now)` as JSON, the catalogue |
| Music | `crates/teul-music` | Renders scores through rustysynth + GeneralUser GS to Opus (`app/public/music`) |
| Client | `app/src` | `main.ts` (start-up, screens), `game.ts` (the game and the frame), `engine.ts` (wrapper over the wasm), `pixel/scene.ts` (rendering), `ui/*` (windows) |
| Content | `scripts/*.py` → `content/base/pack.json` | See [content.md](content.md) |
| Android | `app/android`, `scripts/build-apk.sh` | Capacitor 8, WebView, permissions `INTERNET`, `VIBRATE` |
| Desktop | `desktop/src-tauri` | Tauri 2 (Windows, Linux): the same `app/dist` build, the data key in the system password store, "Save"/"Open" dialogs ([release.md](release.md)) |
| Platform | `app/src/platform.ts` | What differs between phone, desktop and browser: files, secrets, exit |

## Events and the log

- **Command → events.** The client sends a `Command` (`core.rs`: `Travel`, `Use`, `Cook`, `StartShift`, `Lesson`, `OrderBuild`, `Adopt`…; 96 variants). The core first plans it without changing the state (`plan_*`), then records `Event::Input { cmd }` and the outcome events (`event.rs::EventKind`), which are applied to `DeltaState` (`state.rs`).
- **Time.** The client passes Unix seconds; the core turns them into world minutes (`time::WorldClock`). The clock never goes back (`ClockWentBackwards`). Within a session the client takes `min(wall, last + monotonic)`.
- **Derived things are not stored.** Most of the world is a pure function of the seed, the content and the calendar: life, feelings, the town's growth, the sky, holidays, the paper, warmth. Only what the player did is stored.
- **Randomness** is `rng.rs`: stateless, random-access randomness where every value is a function of its inputs (a `Domain` per subsystem).

## Honest play (see [world-economy.md §6](world-economy.md))

1. **Inputs in the log.** On open the core re-executes every input and requires the stored events to match.
2. **The chain.** Every event carries `chain = H(prev, device, seq, time, kind, secret)`. Any edit, insertion or deletion breaks the chain, and the world opens up to the last honest event (`opened.tampered`).
3. **Limits.** At most 40 commands per world minute (`TooFast`), daily caps at stations and jobs.
4. **Snapshots.** At the first command of each world day (and after 400 inputs) the core makes a snapshot with a MAC (`snapshot_mac`). Opening = the latest snapshot that verifies + the tail of the log.
5. **No hooks in release.** `window.__teul` exists only in non-production builds.

## The client frame (`game.ts::frame`)

1. **Frame rate.** While walking, frames come at the display's rate. Other movement is drawn 30 times a second, a still room 8–12 times a second.
2. **Frame logic:**
   - movement of the hero (`stepWalker`), the pet and the car;
   - `checkTown` (town flags every 1.5 s);
   - `updateNpcs` (residents' poses from `life_view`, `townfeel.ts`);
   - the action button;
   - every half second the clock, the weather, warmth (`updateComfort`), the jail check.
3. **Building the `Frame`.** It holds the room, the figures (`npcsSeated` = NPCs + residents + rift creatures + night horrors + town figures), moving cars, lights, the season, cloud cover, fireworks, the nuclear plant on the horizon.
4. **Rendering:**
   - `SceneRenderer.draw` (`pixel/scene.ts`): sky → static layer (floor, walls, shadows) → entities sorted by depth → overlays → daylight and tint → light of lamps and fire → weather;
   - then the feeling layer (`ui/feel.ts`, `skin`), the rift shader (`wonders/post.ts`) and name labels.
5. **Quality.** `tuneQuality`: if 20 frames in a row are late, the level of detail drops (`level` 0–2, `lowDetail`, `minimal`).

## Caches and performance

- **Item sprites.** `pixel/items.ts::itemSprite` caches at most 2400 of them. Key: id, kind, rotation, colours, props, glow, seasonal variant.
- **Figure sprites.** `character.ts::remember` caches layers by look, direction, pose and frame. `scene.layerSprite` is a `WeakMap` keyed by the identity of the layer array.
- **Joined layers.** `layers.ts::joinLayers` returns the same array for the same parts (a person + a pram, a cane, a phone). Without it the sprite was redrawn every frame.
- **Pre-drawing.** `scene.prewarm`/`warmUp` draws one sprite of each kind in advance, with the same keys the renderer uses, starting with the nearest. Large things (over 16 cells in area) are drawn only when they first appear on screen.
- **Measurements.** `e2e/perf.mjs` with `?perf` (`perf.ts::FramePerf`) and `renderer.prof`. Measured in headless Firefox (software rendering), average frame: the town by day ≈ 6.5 ms, in the evening ≈ 10 ms, the forest ≈ 4.7 ms, the café ≈ 7.3 ms. Recomputing life at midnight ≈ 5 ms. The longest frames (70–270 ms) happen on first entering a location, and the fade hides them.

## Language (`i18n.ts`, `lang/*`, `Content::lang`)

- **Client.** `t(key, params)` takes words from the tables `app/src/lang/*.ts` (`'key': ['Ukrainian', 'English']`, holes `{name}`, plural forms separated by `|` by `{n}`). The language comes from the settings (`teul.lang`), the first time from the device's language; changing it reloads the page.
- **Content.** `content/base/en.json` is a text overlay over the pack (by id and field). The client passes it to `Engine.retext`; the core builds the content with the overlay (`Content::from_packs_in`) but keeps the pack's fingerprint as it is, so the log, the chain and the snapshots are the same for both languages (`tests/lang.rs`).
- **Core.** Texts the core composes (the paper, news, holidays, the sky, the nuclear plant, driving stories, feelings) choose their language through `Content::lang` (`Lang::pick`). Logic never compares translated text: where needed there are stable kinds (`weekday_id`, the story kind in the id).

## Saves

- `storage.ts`: IndexedDB (the log with the index `[time, id.device, id.seq]`, the two latest snapshots, metadata, daily automatic copies). Without IndexedDB the world lives only in memory.
- A new world starts at local midnight of the day it was created (`worldEpoch`).
- A device can hold several worlds (`worlds.ts`: the first is the database `teul`, others are `teul-w<id>`); a second one appears when a backup is opened "alongside" the current world.
- **The world's key.** Each world has an ed25519 pair whose seed stays with the shell; the core only derives its public half (`keys.rs`), by which the shell names the world's storage.

### Encryption on the device

- **The data key.** One random AES-256 key per device (`secure/keystore.ts`). The platform holds it: Android — the Keystore (through `@aparajita/capacitor-secure-storage`, AES-GCM under a Keystore key); desktop — the system password store (Windows Credential Manager, Secret Service on Linux; the Tauri commands `secret_get`/`secret_set`, and without a password service a `secrets.json` file with permissions 0600 in the app's data folder); browser — a non-exportable CryptoKey in the IndexedDB database `teul-keys`. The browser variant protects against reading the save files, but not against scripts on the same page.
- **What is sealed** (`secure/seal.ts`: AES-256-GCM, a fresh 96-bit nonce per record, the record's place as additional authenticated data): the world's metadata (seed, chain secret, world key), every event of the log, snapshots, workshop items, automatic copies. Only the time, the device and the event number stay in the clear, because the log is ordered by them. A record moved to another place, changed, or sealed with another key does not open.
- **Private web-storage entries** (`secure/vault.ts`): the computer's diary. The game reads them synchronously: at start-up they are unsealed into memory, and every write is sealed and stored at once (`teul.sealed:<key>`).
- **Moving from an older version** is transparent, on the first start: an old plain record is read, sealed, checked by unsealing, all records are written in one transaction (either the whole world is sealed or it stays as it was) and read once more (`IdbStore.sealAtRest`, `Vault.open`). The mark `at_rest = 2` in the metadata says nothing more is to be done.
- **The key is gone** (the app's data was cleared, Android moved the data without the Keystore): the save is not overwritten. The game says so in its own words and offers to open a backup or to start a new world alongside (`keeping.ts::cannotOpen`). That is why the system backup is switched off on Android (`allowBackup="false"`): a world is moved with the "Backup" file.

### Backup and moving

- Settings → "Backup" (`ui/backup.ts`, `keeping.ts`, `backup.ts`). The whole world — the log, snapshots, metadata, workshop items and settings — in one file, `lypove-YYYY-MM-DD.teulbackup`. The file is sealed with the player's passphrase: PBKDF2-SHA-256, 600,000 rounds, a 16-byte salt → AES-256-GCM, with the file header (version, salt, rounds) as additional authenticated data. The contents are gzip-compressed. The passphrase is at least 8 characters.
- The platform saves it (`platform.ts::saveFile`): on a phone, the "Share" menu (Files, a messenger, a drive); on a computer, the system "Save as" dialog; in a browser, a download. Opening is `openFile` (a file picker).
- An opened copy either **replaces** this world (today's state goes into the day's automatic copy first) or becomes **a separate world alongside**. Every choice asks again in plain words. A wrong passphrase, someone else's file, a copy from a newer version — each is explained without technical words (`backup.ts::problemText`).
- **Automatic copies:** once a day the game puts a copy of the world into the database by itself (sealed with the data key); the last three days are kept, and they can be brought back from the same place.

### Save integrity and compatibility

A new version must open every save made by any older one. The rules:

1. **Never rename or remove** variants of `Command` and `EventKind`, their fields (new fields only with `#[serde(default)]`), or content ids (items, styles, places, people, stations, recipes…). What the game no longer has is not removed but **retired** (see below). This is checked by `variants_kept.rs` (the 1.0 variant lists in `tests/fixtures/*_variants.txt`; a retired variant may not also be live) and `content_ids_kept.rs` (every 1.0 id in `tests/fixtures/content_ids.txt` is live, aliased or retired).
2. **A content id may be renamed or merged** only with an alias in the pack: `"aliases": { "old_id": "new_id" }` (`alias.rs`). While replaying the log the core reads the old id as the new one — in the command it plans again, in the events and in the snapshot; the chain and the MAC are checked against the real records, so nothing is rewritten. Alias chains are followed; cycles and an alias of a live id are content errors. Limits: an id looks like `[a-z0-9_.:-]`; free text (names) is not touched, nor are values under a `type` key.
3. **The client's save format** is `savefmt.ts::SAVE_FORMAT` (1 — before 1.0, 2 — sealed, with `format`, `content`, `app` in the metadata). If you change what is saved, add a step `STEPS[n]` (steps never change after a release). A save in a newer format is neither opened nor overwritten: the game asks to be updated.
4. **Golden saves** (`crates/teul-core/tests/fixtures/saves`, [testing.md](testing.md#golden-saves)) must open whole. They are never rewritten.
5. The core can open a log made with other content: for other packs it compares only the kinds of the outcomes (`Core::replay_from`), and `rules_version`/`world_version` guard against a log from a newer core.

**How 1.x saves open.** Version 1.x had things this version does not: the world beyond the edge of Lypove, friends, parcels, guests, horses, mines, the forge. A save holding them opens whole:

- **Retired events and commands.** Events listed in `event::RETIRED_EVENTS`, and inputs of commands listed in `event::RETIRED_COMMANDS`, are read as `EventKind::Retired`: the body is kept as it was read, so the log writes back byte for byte and still chains. Their link in the chain is taken as read, but the next live event's link must still follow from it.
- **What the replay passes over.** A group with a retired event, a way to a place the game no longer has, and everything done while the player was out there are passed over and counted in `Integrity::retired` (and `Snapshot::retired`), never as tampering. The way back home counts where it led: the player is where they walked to (home, or a place of Lypove).
- **Retired items.** Items of 1.0 the game no longer has are listed in the pack's `retired` list (`portal_gate`, `bridge`, `planter_box`). An input naming one is retired, and after the replay these items leave the home and the inventory.
- **Snapshots.** 1.x snapshots that held friends' state no longer verify: the core refuses them (`CoreError::SnapshotRefused`), the shell opens the whole log instead (`engine.ts::loadEngine`), and a new snapshot is made afterwards.
- **Web storage.** The web-storage entries of 1.0's network features (keys, contacts, mailbox) are removed when the vault opens (`Vault.open`, logged once to the console); backups no longer carry them, and restoring a 1.0 backup skips them (`secure/vault.ts::isRetired`, `backup.ts`).
- **Tests.** `crates/teul-core/tests/golden_saves.rs` (the 1.0 golden saves, the pair of friends among them, open whole with the exact count of what was retired), `crates/teul-core/tests/retired.rs` (a hand-made 1.x log with the world beyond the edge and friends: `a_save_that_went_beyond_the_edge_opens_whole_without_it`, `the_way_back_from_beyond_counts_where_it_leads`, `a_retired_event_reads_writes_back_and_still_chains`, `the_world_goes_on_after_and_its_new_snapshot_opens_the_same`, `the_green_gate_of_1_x_leaves_the_home`), `app/test/compat.test.ts` (the same golden saves in the client), `app/test/sealed.test.ts` (retired storage entries).

### Updates without a mix of old and new

- Android and the desktop carry the game's files inside the installed app: an update replaces them together. Capacitor Live Updates are not used.
- In a browser the scripts and the core's wasm have content-hashed names, so a new `index.html` can load only the new ones. On the first start of a new build (`update.ts`, `__BUILD_ID__`) the game unregisters any service workers and clears Cache Storage that older versions may have left. Hosting must serve `index.html` with `Cache-Control: no-cache`.
