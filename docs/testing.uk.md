# Тести

[English](testing.md)

**Коротко.**
- **Ядро:** `cargo test`, понад 480 тестів у `crates/teul-core/tests` (одна тестова програма `tests/all.rs`) і модулях.
- **Клієнт:** `vitest`, понад 480 тестів у `app/test`.
- **Вміст:** скрипти перевірки економіки й історій.
- **e2e:** 35 сценаріїв в справжньому безголовому Firefox через WebDriver BiDi (`scripts/bidi.mjs`). Вони працюють проти `vite preview` e2e-збірки з тестовим хуком `window.__teul`.
- **Інструменти, не тести:** фотосесія (`shoot.mjs`) і заміри продуктивності (`perf.mjs`).

## Як запускати

```bash
cargo test                                  # або scripts/check.sh — перевірки за зміненими файлами; --full — усе
python3 scripts/check_economy.py && python3 scripts/check_quests.py
cd app && npx vitest run --testTimeout=30000   # важкий тест гардероба на завантаженій машині
npm run build:e2e && npx vite preview --port 4300 --strictPort &
BASE=http://localhost:4300/ node e2e/flows.mjs
BASE=http://localhost:4300/ node e2e/growth.mjs /шлях/до/знімків   # багато сценаріїв приймають теку для знімків
```

`scripts/check.sh --full` обов'язковий перед злиттям і перед релізом; `--no-e2e` пропускає e2e, `--base REF` порівнює з іншою гілкою.

## Тестові прапорці URL (лише непродакшн-збірки)

| Прапорець | Що робить |
|---|---|
| `?debug` | `window.__teul = { game, engine, … }`, профілювання рендеру |
| `?skip` | Без заставки, одразу у світ |
| `?shift=<хв>` | Годинник світу вперед на стільки хвилин (світ іде лише вперед, тож кожен момент — у свіжому світі) |
| `?rich` | Окремий тестовий світ із 6000 монет |
| `?lang=en` / `?lang=uk` | Мова на цю сесію (без збереження) |
| `?world=<id>` | Інший тестовий світ (два світи в одному браузері) |
| `?perf` | `game.perf` (`FramePerf`): таймер секцій кадру |

У релізі (`vite build`, APK) нічого з цього немає.

## Модульні тести клієнта (`app/test`, приклади)

- **Рендер і геометрія:** `character`, `seats`, `layers`, `iso`, `geometry`, `path`, `village`, `models`, `occupant`, `facing` (машини носом уперед).
- **Системи:** `faiths`, `growth`, `festive`, `parade`, `topics`, `warmth`, `wear`, `drive`, `feel`, `horror`, `wonders`, `rift`, `media`, `musicplayer`, `paperphoto`, `away`.
- **Збереження:** `storage`, `history`, `engine` (через справжній wasm).
- **Шифрування й копії:** `sealed` (AES-GCM туди й назад, підміна байта / місця / ключа, перенесення старого відкритого збереження, записи мережевих можливостей 1.0 видаляються), `backup` (експорт → імпорт на «іншому пристрої» дає той самий хеш стану, неправильна фраза, автокопії за днями), `compat` (золоті збереження 1.0 — див. нижче).

## Тести ядра (`crates/teul-core/tests`, приклади)

- **Вміст:** `base_content.rs` (справжній пакет: завантаження, накладання, дороги, досяжність, перша сесія, таксі, коло на повню, храм).
- **Чесність і збереження:** `determinism.rs`, `honesty.rs`, `snapshots.rs`, `core_hardening.rs`.
- **Сумісність оновлень:** `golden_saves.rs` (золоті збереження 1.0 з повного журналу й зі знімка), `retired.rs` (зроблений вручну журнал 1.x зі світом за межею й друзями відкривається цілим, вилучене рахується окремо, а не як підробка), `variants_kept.rs` (жоден варіант команди чи події 1.0 не зник, хіба що вилучений), `content_ids_kept.rs` (жоден id вмісту 1.0 не зник без псевдоніма чи списку вилученого), `aliases.rs` (перейменований id: старе збереження відкривається цілим).
- **Календар:** `calendar_days.rs` (дні тижня, Великдень, свята, школа, розломи, повні), `calendar_quests.rs`.
- **Життя:** `life*.rs`, `feelings.rs`, `town.rs`, `growth.rs`, `sky.rs`, `paper.rs`.
- **Економіка й дім:** `stations.rs`, `pocket.rs`, `helps.rs`, `quests.rs`, `work.rs`, `garden.rs`, `skills.rs`, `bills.rs`, `fridge.rs`, `cooking.rs`, `craft.rs`, `home_more.rs`.
- **Решта систем:** `style.rs`, `warmth.rs`, `media.rs`, `drive.rs`, `rift.rs`, `taxi_pricing.rs`, `perf.rs`.

Окремо є тести в `crates/teul-music` і `crates/teul-wasm`.

## Золоті збереження

`crates/teul-core/tests/fixtures/saves/*.json` — чотири світи, збережені версією 1.0: новий (`fresh`), прожитий чотири дні, 43 команди (`played`), і пара друзів із посилками в обидва боки (`friends_a`, `friends_b`). Їх зробив один раз `app/test/compat.test.ts`, і більше їх ніхто не переписує. Кожна нова версія мусить відкривати їх цілими — і в клієнті (`compat.test.ts`), і в ядрі (`golden_saves.rs`). Друзів і посилок ця версія вже не має: у `friends_a` і `friends_b` вони пропускаються як вилучені, і тести перевіряють точну кількість вилученого, а все інше (монети, дім) відкривається як було. Упав такий тест — зміна зламала старі збереження: потрібен крок міграції, псевдонім чи вилучення, а не нова фікстура (див. [architecture.uk.md](architecture.uk.md#цілісність-і-сумісність-збережень)). Після кожного релізу варто додати ще одне золоте збереження нової версії.
